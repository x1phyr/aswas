# aswas 功能与使用说明书

> 适用版本：aswas 0.1.0
>
> 支持系统：macOS 14 或更高版本
>
> 文档更新：2026-07-18

aswas 是一款原生 macOS 菜单栏应用，用来把一组 Finder 窗口保存为命名工作区，并在不同任务之间快速切换。它可以记录窗口当前打开的文件夹、窗口位置和尺寸、显示器以及 Finder 视图模式；之后可以在保留现有窗口的情况下打开，也可以经过确认后替换当前 Finder 窗口。

## 1. 产品定位与适用范围

### 1.1 适合的场景

- 在开发、设计、研究等多个项目之间频繁切换。
- 每个项目都需要同时打开多个 Finder 文件夹。
- 希望临时关闭 Finder 窗口，但之后恢复原来的工作布局。
- 使用多显示器，希望尽量恢复窗口所在屏幕和位置。
- 希望工作区数据只保存在本机，不使用账号或云服务。

### 1.2 aswas 管理什么

aswas 管理的是 **Finder 窗口工作区**。一个工作区可以包含多个 Finder 窗口；授予辅助功能权限后，每个窗口还会记录完整标签组、顺序和当前选中项。

### 1.3 aswas 不管理什么

- 不保存文件内容，也不会复制、移动或修改文件。
- 不保存其他应用的窗口，例如浏览器、终端或编辑器。
- 不保存 Finder 当前选中的文件、滚动位置、排序条件、侧边栏或搜索内容。
- Finder 标签页增强依赖辅助功能权限，详见[第 14 节](#14-当前限制)。
- 不提供账号、云同步、遥测或统计分析。

## 2. 系统要求与安装

### 2.1 系统要求

- macOS 14 或更高版本。
- 从源码构建时需要 Xcode 16 或更高版本，并包含 Swift 6 工具链。
- 保存或恢复工作区时需要 Finder 自动化权限。
- 完整保存和恢复 Finder 标签页需要“辅助功能”权限；未授权时仍可使用窗口级工作流。

### 2.2 从源码构建

```sh
git clone https://github.com/x1phyr/aswas.git
cd aswas
swift test
./Scripts/build-app.sh
open build/Release/aswas.app
```

构建结果位于：

```text
build/Release/aswas.app
```

本地构建使用临时签名并启用 Hardened Runtime，适合本机测试。对外分发前需要 Developer ID 签名和 Apple 公证，具体流程参见[发布与公证](Release.md)。

### 2.3 建议的安装位置

日常使用和“登录时启动”功能建议把稳定签名的 `aswas.app` 放入：

```text
/Applications/
```

如果应用路径、签名身份或 bundle identifier 发生变化，macOS 可能会重新询问 Finder 自动化权限。

## 3. 首次启动与权限

### 3.1 启动后的表现

- aswas 图标出现在 macOS 菜单栏。
- 默认不显示 Dock 图标，这是菜单栏应用的预期行为。
- 点击菜单中的“打开 aswas”可以显示工作区资料库主窗口。

### 3.2 Finder 自动化权限

aswas 通过 AppleScript 读取和操作 Finder 窗口。首次执行保存、恢复或主动请求权限时，macOS 会询问是否允许 aswas 控制 Finder。

请选择“允许”。如果之前选择了拒绝：

1. 打开 macOS“系统设置”。
2. 进入“隐私与安全性 → 自动化”。
3. 找到 aswas，并允许它访问 Finder。
4. 回到 aswas 的“设置 → 权限”，点击“重新检查”。

### 3.3 辅助功能权限

辅助功能权限用于读取 Finder 标签栏、切换标签页，以及恢复标签顺序和选中项。点击“设置 → 权限 → 请求辅助功能权限”，在系统设置中启用 aswas，然后返回应用点击“重新检查”。

如果不授予该权限，aswas 仍会按窗口分组并保存所有标签页路径，但无法可靠确认界面顺序和当前选中项，恢复完整标签组也需要该权限。

## 4. 核心概念

### 4.1 工作区

工作区是一个带名称的 Finder 状态快照，包括多个可读取 Finder 窗口及其布局信息。每个工作区都有稳定 UUID、创建时间和更新时间。

### 4.2 保存当前工作区

读取当前所有可读取的 Finder 窗口，创建一个新的工作区，但不关闭窗口。

### 4.3 保存并关闭

先把当前 Finder 窗口完整保存到本地；只有保存成功后，才精确关闭刚才捕获到的窗口。

### 4.4 打开恢复

根据工作区创建新的 Finder 窗口，保留当前已经打开的 Finder 窗口。适合希望叠加两个工作区的情况。

### 4.5 替换恢复

先预览当前可读取的 Finder 窗口并要求确认；确认后关闭当前 Finder 窗口，再恢复目标工作区。

### 4.6 更新工作区

使用当前 Finder 窗口替换某个已有工作区的内容，同时保留该工作区的名称、UUID 和创建时间，并更新“最后修改时间”。更新前会生成旧版本备份。

## 5. 界面与按钮说明

### 5.1 菜单栏菜单

| 菜单项 | 功能 |
| --- | --- |
| 恢复上一个工作区 | 恢复最近保存或更新的工作区，使用“默认恢复模式”设置。 |
| 工作区 | 显示所有已保存工作区；点击名称后使用默认恢复模式。 |
| 保存当前工作区 | 输入名称并保存当前 Finder 窗口，不关闭窗口。 |
| 保存并关闭 | 保存成功后关闭本次捕获到的 Finder 窗口。 |
| 打开 aswas | 打开工作区资料库主窗口并置于前台。 |
| 设置 | 打开设置窗口并置于前台。 |
| 退出 | 退出 aswas；不会删除工作区数据。 |

“恢复上一个工作区”指最近**保存或更新**的工作区，并不记录最近一次点击恢复的工作区。

### 5.2 工作区资料库主窗口

主窗口按最后更新时间倒序展示工作区。每行包含：

- 工作区名称。
- 保存的窗口数量和文件夹数量。
- 相对更新时间。
- “恢复”按钮。该按钮使用设置中的默认恢复模式。

顶部“新建/保存”菜单提供：

- 保存当前工作区。
- 保存并关闭。

#### 工作区右键菜单

| 操作 | 说明 |
| --- | --- |
| 打开恢复 | 保留现有 Finder 窗口并恢复工作区。 |
| 替换恢复 | 经过预览和确认后替换当前 Finder 窗口。 |
| 更新 | 用当前 Finder 窗口覆盖该工作区。 |
| 更新并关闭 | 更新成功后关闭本次捕获到的窗口。 |
| 重命名 | 只修改显示名称，不改变 UUID 文件名或工作区内容。 |
| 删除 | 先备份工作区 JSON，再从资料库删除。 |

### 5.3 工作区详情页

单击工作区行可以打开详情页。详情页提供：

- 工作区名称、窗口和文件夹数量。
- 每个窗口保存的文件夹路径。
- 路径可用性提示：正常文件夹显示文件夹图标，缺失路径显示警告图标。
- 文件夹右侧箭头：直接在 Finder 中打开该路径。
- 更新、更新并关闭、打开恢复和替换恢复按钮。

### 5.4 设置窗口

设置分为“通用”“权限”和“高级”三个标签页，详见[第 9 节](#9-设置说明)。

## 6. 常用操作流程

### 6.1 创建一个工作区

1. 在 Finder 中打开需要保存的文件夹窗口。
2. 调整窗口尺寸、位置和 Finder 视图模式。
3. 点击菜单栏 aswas 图标。
4. 选择“保存当前工作区”。
5. 输入工作区名称。
6. 点击“保存”。
7. 查看结果提示，确认成功保存的窗口数和警告数。

如果当前没有可读取的普通 Finder 窗口，保存会失败并显示提示，不会创建空工作区。

### 6.2 保存并关闭当前 Finder 窗口

1. 点击菜单栏 aswas 图标。
2. 选择“保存并关闭”。
3. 输入工作区名称并确认。
4. aswas 先捕获、校验并写入工作区 JSON。
5. 写入成功后，aswas 按 Finder 窗口 ID 关闭刚才捕获的窗口。

如果捕获、校验或写盘失败，第 5 步不会执行。

### 6.3 在现有窗口旁恢复

1. 打开工作区资料库。
2. 右键目标工作区。
3. 选择“打开恢复”。
4. aswas 为仍然存在且可访问的路径创建新的 Finder 窗口。
5. 原有 Finder 窗口保持不变。

### 6.4 替换当前 Finder 窗口

1. 右键目标工作区，选择“替换恢复”。
2. 查看即将替换的当前 Finder 窗口路径预览。
3. 选择“取消”，不会关闭任何窗口。
4. 选择确认后，aswas 精确关闭当前可读取的 Finder 窗口。
5. aswas 恢复目标工作区。

其他应用窗口和普通文件选择对话框不属于 aswas 工作区，不会被当作 Finder 工作区窗口批量关闭。

### 6.5 更新已有工作区

1. 打开并整理新的 Finder 窗口布局。
2. 在资料库中右键已有工作区。
3. 选择“更新”或“更新并关闭”。
4. aswas 先备份旧 JSON，再写入当前 Finder 状态。

“更新并关闭”遵循与“保存并关闭”相同的保存优先规则。

### 6.6 重命名工作区

1. 右键工作区并选择“重命名”。
2. 输入非空名称并确认。
3. 只改变工作区显示名称；底层 JSON 文件仍使用原 UUID 文件名。

### 6.7 删除工作区

1. 右键工作区并选择“删除”。
2. 阅读确认提示并确认。
3. aswas 先把当前 JSON 复制到 `backups/`，再删除资料库中的记录。

## 7. 保存的数据与未保存的数据

### 7.1 当前保存的数据

对于每个可读取 Finder 窗口，aswas 保存：

- 当前文件夹的 POSIX 路径。
- 获得辅助功能权限时：完整标签页路径、标签顺序和当前选中项。
- Finder 显示名称。
- 窗口位置和尺寸。
- 相对于显示器的归一化位置。
- 显示器标识、可见区域和缩放信息。
- Finder 视图模式：图标、列表、分栏或画廊。
- 工作区名称、UUID、创建时间、更新时间和数据结构版本。

### 7.2 当前不保存的数据

- 文件本身或文件内容。
- Finder 当前选中的文件。
- 排序、分组、图标大小、列宽、侧边栏状态或滚动位置。
- Finder 搜索条件和智能文件夹内部查询状态。
- 其他应用的窗口。

### 7.3 `tabs` 数据结构

每个 Finder 窗口使用 `tabs` 数组保存标签页路径，并通过 `selectedTabIndex` 保存当前选中项。Finder 脚本会把标签页返回为多个窗口式条目，aswas 根据共同的物理窗口边界进行分组；获得辅助功能权限后，再用只读标签栏信息校正顺序和选中项。

## 8. 恢复规则与异常处理

### 8.1 路径不存在或不可访问

- 不存在、离线或无权限的文件夹会被跳过。
- 其他有效文件夹继续恢复。
- 结果提示会汇总跳过和警告数量。
- aswas 不会猜测路径的新位置，也不会自动替换成同名文件夹。

外接硬盘、网络共享和云盘目录恢复前，请先确认相应存储已经挂载并可访问。

### 8.2 显示器发生变化

- 如果原显示器仍存在，优先按保存的显示器和相对位置恢复。
- 如果原显示器不存在，窗口会回退到主显示器。
- 如果原位置落在屏幕外，窗口会被调整到可见区域。
- 过小的窗口会被调整到合理的最小尺寸。

显示器分辨率、缩放比例或排列变化时，恢复位置可能是近似值。

### 8.3 Finder 视图模式恢复失败

Finder 或特定目录可能拒绝某种视图模式。此时文件夹窗口仍会打开，但结果中会出现视图恢复警告。

### 8.4 并发操作

aswas 会串行执行保存和恢复操作。快速重复点击不会启动相互竞争的恢复任务；应用会提示已有操作正在进行。

### 8.5 部分成功

恢复采用尽力执行策略。一个窗口失败不会取消已经成功恢复的其他窗口。最终提示会显示成功窗口数以及警告或错误数量。

## 9. 设置说明

### 9.1 通用

#### 语言

- 跟随系统。
- English。
- 简体中文。

切换后菜单栏、主窗口、设置和用户提示会立即更新。

#### 登录时启动

通过 Apple `SMAppService` 注册或取消注册 aswas。为保证路径稳定，建议使用放在 `/Applications` 中的标准应用包；直接运行 SwiftPM 可执行文件时，该功能可能不可用。

#### 默认恢复模式

- **打开**：保留现有 Finder 窗口。
- **替换**：预览并确认后替换当前 Finder 窗口。

默认恢复模式影响：

- 菜单栏“恢复上一个工作区”。
- 菜单栏“工作区”子菜单中的工作区名称。
- 主窗口每行的“恢复”按钮。

右键菜单和详情页中的“打开恢复/替换恢复”是显式操作，不受默认模式影响。

#### 替换前确认

当前版本始终要求确认，不能关闭这项保护。设置项显示为固定启用状态。

### 9.2 权限

- 显示 Finder 自动化权限状态。
- 显示辅助功能权限状态。
- “请求 Finder 权限”会触发 Finder 自动化授权流程。
- “请求辅助功能权限”会打开 macOS 的辅助功能授权流程，用于完整标签页保存和恢复。
- “重新检查”会刷新权限状态和工作区列表。

### 9.3 高级

- “打开数据文件夹”会在 Finder 中显示 aswas 的本地数据目录。
- 页面同时显示完整数据目录路径，便于复制和排查。

## 10. 本地数据、备份与隐私

### 10.1 数据目录

```text
~/Library/Application Support/aswas/
├── workspaces/   # 当前工作区
├── backups/      # 更新和删除前的备份
└── corrupt/      # 无法解析的损坏文件
```

### 10.2 工作区文件

每个工作区对应一个 JSON 文件：

```text
workspaces/<工作区 UUID>.json
```

文件名不使用用户输入的工作区名称，避免特殊字符或重命名影响存储。

简化后的结构示例：

```json
{
  "schemaVersion": 1,
  "id": "工作区 UUID",
  "name": "设计项目",
  "createdAt": "ISO-8601 时间",
  "updatedAt": "ISO-8601 时间",
  "finder": {
    "windows": [
      {
        "tabs": [
          {
            "path": "/示例/文件夹",
            "displayName": "文件夹"
          }
        ],
        "selectedTabIndex": 0,
        "frame": {},
        "normalizedFrame": {},
        "display": {},
        "viewMode": "list"
      }
    ]
  }
}
```

不要在应用运行时手工编辑 JSON。格式或字段不合法的文件会被视为损坏记录。

### 10.3 备份规则

- 更新工作区前，旧 JSON 会复制到 `backups/`。
- 删除工作区前，当前 JSON 会复制到 `backups/`。
- 备份文件名包含工作区 UUID、时间戳和随机 UUID。
- 当前版本不会自动清理历史备份。

### 10.4 损坏文件隔离

如果某个工作区无法解析，它会被移动到 `corrupt/`。其他健康工作区仍然可以正常加载。

### 10.5 隐私

- 工作区数据只保存在本机。
- 没有账号、云同步、遥测或分析 SDK。
- 正式构建日志不会公开完整私有路径。
- JSON 本身包含文件夹路径；共享或上传数据目录前应先检查并脱敏。

## 11. 安全机制

### 11.1 保存成功后才关闭

“保存并关闭”和“更新并关闭”必须依次完成：

1. 捕获 Finder 窗口。
2. 校验工作区结构。
3. 原子写入 JSON 并同步到磁盘。
4. 保存成功后才开始关闭窗口。

任何前置步骤失败都不会进入关闭流程。

### 11.2 精确关闭窗口

aswas 保存捕获时返回的 Finder 窗口 ID，并逐个关闭这些窗口。它不会发送 `close every window` 之类的全量关闭命令。

### 11.3 替换必须确认

替换恢复会展示当前可读取 Finder 窗口的路径预览，并且始终要求确认。取消操作不会关闭窗口。

### 11.4 原子存储与隔离

工作区先写入临时文件并同步，再移动或替换正式文件。损坏文件单独隔离，避免一个错误记录阻塞整个资料库。

## 12. 常见问题与故障排查

### 12.1 菜单栏没有 aswas 图标

- 确认应用仍在运行。
- 检查菜单栏图标是否因为空间不足被隐藏。
- 重新启动 `aswas.app`。
- aswas 默认没有 Dock 图标，不应以 Dock 图标判断是否运行。

### 12.2 点击设置后没有看到窗口

- 设置窗口会主动把 aswas 激活到前台。
- 如果仍未出现，检查是否位于其他桌面空间或全屏应用之后。
- 退出并重新启动最新构建，避免仍在运行旧版本。

### 12.3 提示没有 Finder 权限

1. 打开“设置 → 权限”。
2. 点击“请求权限”。
3. 如果没有系统弹窗，在 macOS“隐私与安全性 → 自动化”中检查 aswas → Finder。
4. 授权后点击“重新检查”。
5. 如果应用签名或位置刚刚变化，退出并重新启动应用后再次尝试。

### 12.4 提示没有可读取的 Finder 窗口

- 至少打开一个指向普通文件夹的 Finder 窗口。
- Finder 桌面、特殊面板或无法读取目标路径的窗口可能被跳过。
- 检查 Finder 自动化权限。

### 12.5 恢复时少了某些文件夹

- 打开工作区详情，检查是否显示缺失路径警告。
- 确认外接磁盘、网络共享或云盘已经连接。
- 如果文件夹已经移动，使用 Finder 打开新位置，然后“更新”工作区。

### 12.6 窗口位置与原来不同

- 检查显示器是否被拔出、重排或更改缩放比例。
- aswas 会优先保证窗口可见，因此可能调整屏幕外位置或过小尺寸。
- Finder 自身也可能限制特定窗口尺寸。

### 12.7 视图模式没有恢复

部分 Finder 位置可能不接受某种视图模式。窗口仍会打开，aswas 会在结果中给出警告。可以在 Finder 中调整后更新工作区。

### 12.8 登录时启动失败

- 将标准 `aswas.app` 移到 `/Applications` 后再尝试。
- 不要频繁移动已注册的应用包。
- `swift run aswas` 不是适合测试登录启动的标准应用安装方式。

### 12.9 工作区列表中少了一条记录

- 打开“设置 → 高级 → 打开数据文件夹”。
- 检查对应文件是否被移动到 `corrupt/`。
- 不要直接把不完整 JSON 放入 `workspaces/`。
- 可以从 `backups/` 找到旧版本，但手工恢复前应先复制整个数据目录并退出 aswas。

### 12.10 连续点击恢复只执行了一次

这是预期保护。aswas 不允许同时运行多个恢复任务，以免创建重复窗口或产生互相竞争的关闭操作。

## 13. 升级、备份与卸载

### 13.1 升级应用

替换 `aswas.app` 不会自动删除工作区数据。升级前建议备份：

```text
~/Library/Application Support/aswas/
```

如果新版本使用不同签名身份，macOS 可能重新请求 Finder 自动化权限。

### 13.2 备份和迁移数据

1. 退出 aswas。
2. 复制整个 `~/Library/Application Support/aswas/` 目录。
3. 在目标电脑安装兼容版本的 aswas。
4. 确认目标电脑上的 aswas 已退出。
5. 把备份复制到相同位置。
6. 启动 aswas 并检查工作区。

路径中可能包含原电脑不存在的目录；这些路径在恢复时会被跳过。

### 13.3 卸载

- 删除 `aswas.app` 只移除应用，不会删除工作区数据。
- 如果启用了登录时启动，建议先在设置中关闭。
- 如果希望完整移除个人工作区数据，先备份需要保留的内容，再手动处理 `~/Library/Application Support/aswas/`。

## 14. 当前限制

### 14.1 Finder 多标签页

Finder 公共 AppleScript 字典没有专用标签页接口，因此 aswas 使用辅助功能 API 读取和操作标签栏，再用 Finder 自动化取得每个标签页的真实目录。该增强能力有以下边界：

- 必须在“系统设置 → 隐私与安全性 → 辅助功能”中授权 aswas。
- 保存过程只读 Finder 标签栏，不会逐个切换或修改现有标签页。
- 恢复标签页是串行操作，标签较多时需要等待。
- Finder 界面结构可能随 macOS 版本变化；读取失败时仍保存窗口分组和全部路径，但顺序及选中项会显示警告。
- 未授权时不会尝试模拟操作 Finder 标签栏。

### 14.2 Finder 状态精度

窗口位置、尺寸和视图模式是尽力恢复。显示器变化、Finder 限制、特殊目录或系统版本差异都可能产生警告。

### 14.3 分发状态

当前仓库提供源码构建和签名/公证流程，但路线图中的正式签名下载版本仍待发布。
